适配 Pi 0.85.1

pig 锁 0.84.1。最新 npm 是 0.85.1。这是协议换代，不是补丁升级。

0.84.1 → 0.85.1

本地 SDK（SessionManager / createAgentSession）还在。远程 GUI 栈整层换了。0.85.1 还把 pi-coding-agent/client 收成 source-only 再导出。

pig 现在 0.84.1

  • 协议 v1：类型化 CBOR（hello / snapshot / command）
  • PiClient + RemoteSession
  • PiServer(PiHostService)
  • 权威状态：ServerSnapshot / SessionSnapshot
→

最新 npm 0.85.1

  • 协议 v8：路由信封 + 不透明 JSON 载荷
  • Client + Chord 服务（无 RemoteSession）
  • Server(ServerHost)
  • 权威状态：Chord 复制状态；协议不管业务 schema

可留 传输与壳层

WebSocket 仍是有序字节流。platform HTTP 是 pig 自己的 Thin Host，Pi 协议不拥有它。

  • ByteTransport / /api/v1/pi
  • 选目录、卡片、历史分页、改名、删除、占用
  • 本地 SessionManager 跑 Agent

必换 远程领域层

pig 现在当领域 API 用的那些符号，0.85.1 里已经不存在或语义变了。

  • PiClient / RemoteSession
  • PiServer / PiServerService / PiSessionRuntime
  • ServerSnapshot SessionSnapshot TranscriptItem（协议包不再导出）

目标调用形状

传输还是同一条 WS。上面换成「握手拿 serverId → Chord 服务目录 → attach Session」。UI 不再订阅一张总快照。

现在 0.84.1
PiClient.connect()
  → ServerSnapshot { sessions, models }
RemoteSession.create / open
  → SessionSnapshot
submit / abort / setModel
  → 同一连接上的 command
历史全文
  → pig HTTP /transcript
目标 0.85.1
Client.connect({ serverId, transportFactory })
  → ServerHello { version: 8, serverId }
subscribeService(server, "SessionDirectory")
subscribeService(server, "Models")
SessionManagement.attach(sessionId)
  → attachment { serverId, sessionId, attachmentId }
request(sessionTarget, { serviceId, member, args })
  → prompt / abort / setModel
subscribeService(session, "Transcript")
  → Chord snapshot + delta

握手之后，业务调用长这样：

const client = await Client.connect({
  serverId, // 逻辑身份，不是端口
  transportFactory: createWebSocketByteTransportFactory({ url }),
})

const dir = await client.subscribeService(
  { serverId: client.hello.serverId },
  "SessionDirectory",
  "singleton",
  (update) => renderSessions(update),
)
dir.start()

await client.request(
  { serverId: client.hello.serverId },
  { serviceId: "SessionManagement", member: "attach", args: [sessionId] },
)
// 真正的路由在 out-of-band attachment 消息里，不在 attach 返回值

按文件动刀

只动远程协议边界。platform HTTP 和 UI 投影尽量留。类型从 pi-protocol 迁走。

留
apps/web/src/client/transport.ts ByteTransport 仍适用。最多加 serverId 发现，不换 WS。
留
apps/web/src/client/platform.ts · packages/gateway/src/server/platform.ts 选目录 / 卡片 / 历史分页 / 改名删除 / 占用。这是 pig Thin Host，不进 Pi 协议。
重写
apps/web/src/client/pi-client.ts PiClient → Client。connect 要带稳定 serverId。不再有 snapshot.sessions / models。
重写
apps/web/src/features/session-workbench/hooks/use-session.ts RemoteSession.create/open/submit/abort/setModel 换成 attach + Chord request/subscribe。
重写
packages/gateway/src/server/host.ts · websocket.ts PiServer → Server；PiServerListener → ServerListener。构造要传入 serverId。
重写
packages/gateway/src/pi/service.ts · session-runtime.ts PiServerService / PiSessionRuntime 没了。改实现 ServerHost：resolveSession / openSession / RoutedSessionHandle.invokeService。
丢掉
apps/web/src/types/common-type.ts 里的协议类型 ServerSnapshot、SessionSnapshot、TranscriptItem 不再从 pi-protocol 出。改从 Chord 绑定或 pig 本地类型来。
等 Pi
@earendil-works/pi-coding-agent/client 0.85.1 只 re-export pi-client，且 source-only。SessionDirectory / SessionManagement 还在 experimental CLI，未作为稳定 GUI SDK 发布。

建议顺序

先不要把 0.85.1 锁进仓库。官方自己说：支持的本地 SDK 和 stdio RPC 不变；实验 client/server 只给 pi-test.sh。

  1. 停在 0.84.1，或只升到 0.84.4 同一套 PiClient / RemoteSession。修模型/工具缺陷可以吃到 0.84.x 补丁。
  2. 等 Pi 发布稳定的 Session Chord 绑定 至少要有可 import 的 SessionDirectory、SessionManagement、Transcript，而不是 coding-agent 源码里的 experimental CLI。
  3. 先改 Gateway 宿主，再改 Web 客户端 Server + serverId + WebSocket listener 能握手 v8，才接 UI。ByteTransport 可复用。
  4. UI 按服务拆订阅 列表、模型目录、Transcript、Turn 控制分成独立 subscribe/request。不要再等一张 ServerSnapshot。
  5. platform HTTP 保持第二条总线 长历史分页和侧栏卡片仍适合 HTTP。不要把它们塞进 Chord。

现在 bump 会断的东西

Web 的 RemoteSession 导入会空。Gateway 的 PiServer / PiServerService 编译失败。pi-protocol 不再有 TranscriptItem。e2e 里按 v1 帧解码 hello 的用例也会立刻挂。
