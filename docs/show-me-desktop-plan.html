对齐稿 · Electron Desktop

Desktop 是壳，不是第二套 pig。

第一刀：Main 拉起现有 Gateway，窗口加载现有 Vue。Agent 链路一行都不改。

你缺的不是 Electron 百科，是三张图：进程怎么分、哪些代码能动、分几步才算落地。

Desktop 真正拥有的

  • 窗口生命周期（创建、单实例、关窗停 Host）
  • 把 Gateway 嵌进 Main，不再用系统浏览器打开
  • 原生选目录：实现已有 DirectoryPort
  • 开发态加载 Vite，生产态加载 Gateway 静态页
  • 以后才做：打包、自动更新、托盘

架构原文：docs/refactor.md — 「新增 Desktop 时，只增加 Desktop shell 与新的 ByteTransportFactory」。v1 连 ByteTransport 都先不换。

新手心智模型

Electron 只有三层。猪的代码对上这三层。

Main · Node

唯一能碰磁盘、端口、原生对话框的地方。

  • new Gateway(...)
  • BrowserWindow
  • dialog.showOpenDialog
  • 注入 DirectoryPort
→

Preload · 隔离桥

v1 几乎为空。禁止把 fs / child_process 暴露给页面。

  • contextIsolation: true
  • sandbox: true
  • nodeIntegration: false
  • 需要时再 contextBridge
→

Renderer · 现有 Vue

就是现在的 apps/web。它不知道自己在 Electron 里。

  • bootstrap hash 兑换凭证
  • WebSocket 连本机 PiServer
  • 选目录仍打 /api/v1/platform/select-directory

一句话：Main 扮演今天的 scripts/dev.ts / cli.ts，Renderer 扮演今天的 Chrome。

推荐架构 · v1

同进程嵌 Gateway，继续走 localhost WS

Electron Main Gateway.start() # 已有类，listen 127.0.0.1:0 HTTP /api/v1/bootstrap HTTP /api/v1/platform/select-directory WS /api/v1/pi → PiServer → PiHostService → Pi SDK GET / → apps/web/dist（生产） ElectronDirectoryPort # 新：dialog.showOpenDialog BrowserWindow.loadURL( dev: http://127.0.0.1:5173/#bootstrap=SECRET prod: http://127.0.0.1:{port}/#bootstrap=SECRET ) Renderer = apps/web（不复制一份） bootstrapFromUrl() → localStorage credential PiClient + 现有 WebSocket ByteTransport Vue UI 原样

为什么不先换 IPC Transport

官方契约已经是 ByteTransportFactory。WS 已打通 create/open/prompt/abort/reconnect。换 IPC 是优化，不是门槛。

为什么不先抽 @pig/ui

docs/refactor-issues.md 写明：useApp 还没切干净就抽包，只会把混乱复制一份。Desktop 不依赖这个拆分。

为什么不把 Gateway 放进子进程

现有 Gateway 就是一个类。new + start() 即可。子进程要处理崩溃、端口、退出码，第二刀再考虑。

新增目录形状

pig/ ├─ apps/web/ # 不动，Renderer 直接用 ├─ packages/gateway/ # 不动，Main import │ └─ native/directory.ts # 已有 DirectoryPort 缝 └─ apps/desktop/ # 本轮只加这里 ├─ package.json ├─ src/main/index.ts # app ready → Gateway → window ├─ src/main/window.ts ├─ src/main/directory-port.ts └─ src/preload/index.ts # v1 空桥，只锁安全开关
明确不做

这些会把你带沟里

  • Renderer 里 require("fs") / 关 isolation
  • 自研 IPC Agent 协议，绕开 PiClient
  • 复制一份 Vue 到 desktop
  • 把 Session / Tool / Transcript 搬进 Main
  • 把 PWA 当成 Desktop（PWA 仍是浏览器平台）
  • 第一周就做自动更新、托盘、多窗口
  • 为 Desktop 再建一套 bootstrap / credential

分期：每期必须能独立验收

D0

对齐（本页）

确认：壳、同进程 Gateway、复用 WS、不抽 UI、选目录走已有 DirectoryPort。

D1

最小窗口 · 和浏览器同一条链路

  • 脚手架 apps/desktop，安全默认全开
  • Main new Gateway({ bootstrapSecret, webRoot? })
  • Dev：Electron 加载 Vite 5173/#bootstrap=
  • Prod：加载 Gateway 自己的静态页 + hash
  • 验收：能建 Session、发 Prompt、看流式、Abort。UI 零改。
D2

原生选目录 · 桌面层的第一个真实价值

  • ElectronDirectoryPort 调 dialog.showOpenDialog
  • 注入 Gateway({ platformPort })
  • Vue 仍打现有 HTTP，Windows / macOS / Linux 都弹出系统对话框
  • 验收：侧栏「添加目录」走原生框，路径仍经 Host canonicalize
D3

像个应用 · 还不打包分发

  • 单实例、窗口尺寸记忆、关窗停 Gateway
  • 最少菜单 / 快捷键（新建 Session、显隐侧栏）
  • 启动失败有可读错误，而不是白屏
D4

打包后置 · 先 Windows

  • electron-builder，先打你本机的 nsis / portable
  • 自动更新、签名、托盘全部更后

需要你点头的决策

决策 建议 备选（后置）
Gateway 放哪 Main 同进程 new Gateway() utilityProcess / 子进程隔离
Agent 传输 继续 localhost WebSocket 以后再写 IPC ByteTransportFactory
启动授权 沿用 #bootstrap=，Main 负责拼 URL preload 注入 credential，去掉 hash 舞
选目录 实现 DirectoryPort，Vue 不改 Renderer 走 preload IPC
UI 拆包 不抽 @pig/ui useApp 切干净后再抽
PWA 和 Desktop 分轨，互不阻塞 不要用 PWA 替代 Electron 壳
打包 D1–D3 能跑再打 第一周就上 builder

D1 验收清单（对齐后就按这个开工）

pnpm --filter @pig/desktop dev 弹出窗口，不是系统 Chrome
窗口里能完成 bootstrap → 连上 Pi → 看到 Session 列表
欢迎页创建 Session、发 Prompt、流式输出、Abort，与浏览器行为一致

apps/web 与 packages/gateway 无 Desktop 专用分叉
